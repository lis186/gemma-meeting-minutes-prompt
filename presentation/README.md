# 兩個 AI 互相對抗，改出一個能用的 prompt

> Hybrid AI 工作坊 2026-08-30 / 5 分鐘 + ccxray 番外 1 分鐘 / Justin Lee
> repo: github.com/lis186/gemma-meeting-minutes-prompt

## 結構：七幕＋番外（英雄 = 對抗迴圈本身）

| 幕 | 時間 | 內容 | 節奏提示 |
|----|------|------|----------|
| 序幕 · 共同經驗 | 0:00–0:25 | 「昨天我們都改了同一份逐字稿」「金牛改好了嗎？」→ 我讓兩個 AI 對抗著改 | 機關槍 |
| 一 · 同一個坑 | 0:25–0:55 | 回馬槍（不解說素材）：日期消失、8/31 掛錯合約、負責人捏造、prompt 打地鼠 | 連珠炮 |
| 二 · 對抗迴圈 | 0:55–2:00 | **動態流程圖**：Fable 改 → Gemma ×3 → Sol 裁決 → 三關 → 一輪一項 | **核心 aha，不砍** |
| 三 · 五輪實錄 | 2:00–3:15 | v1→v5：清單綁錯 → 講道理更糟 → 改結構全對 → 仍有殘餘 | 越點越快 |
| 四 · 天花板 | 3:20–3:50 | Sol 喊停「不值得再改」；15 次 0 全過；誠實結論也是交付 | 停 3 秒 |
| 五 · 三個發現 | 3:50–4:40 | ①結構勝過叮嚀 ②單次不算數 ③專名靠查表 | 重擊三連 |
| 終幕 | 4:40–5:00 | 全公開 + QR（gemma repo） | 停留讓人掃 |
| 番外 · ccxray | 5:00–6:00 | 黑盒子→玻璃盒、npx ccxray claude、QR | 輕快收尾 |

## 伸縮閥

- **太快**：三幕的 v2/v3 各補一個具體錯誤例（「8/31 掛到客戶簽約」「前提被寫成決議」）
- **太慢**：砍五幕的 ②（單次不算數），三個發現變兩個

## 核心段（永遠不砍）

- 二幕動態流程圖（1:10–2:10）：方法本體，全場唯一 aha
- 終幕 QR：分享的目的

## 斷尾方案

落後 2 分鐘 → 砍三、五幕，從流程圖直接跳「Sol 喊停」→ QR 收尾；ccxray 番外只留指令頁＋QR 兩頁

## 流程圖分鏡（fl 頁型，同 DOM 連續動畫）

1. Fable 亮（改 prompt）
2. → Gemma 亮（同 prompt 跑 3 次）
3. → Sol 亮（抓錯、過三關、裁決）
4. 回圈箭頭亮（每輪只改最高槓桿一項）
5. 出口亮（Sol 喊停：「不值得再改」→ 交付）

## Fallback

無 live demo；流程圖為純 HTML/SVG 內嵌動畫，離線可放。瀏覽器異常 → 鍵盤 ←/→ 仍可逐頁講。
